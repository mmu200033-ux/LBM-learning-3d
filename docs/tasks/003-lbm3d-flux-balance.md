# 任务 003：排查通量平衡误差，补全任务 001 缩水的测试

设计文档：`docs/design/lbm3d-cl.md`。引擎在 `lbm3d-cl/src/engine/d3q7.js`，参照 `lbm3d-cl/reference/cl-model/mass_transfer.cu`。

## 背景

任务 001 要求稳态时 |入口通量 − 总反应消耗| / 入口通量 ≤ 1%，但没有做到：

- 任务 001 的测试里没有这一项；第 3 项只检查了剖面单调，没有和 erfc 比较；第 6 项只检查了子步名字和数组长度。
- 设计负责人用 dt = 1e-9 复核时得到 9.3%（M=32）和 13.3%（M=0.032）。**这个复核本身不可靠**：dt 放大 100 倍后缓冲层 τ ≈ 8000，已远离 LBM 的合理区间。所以真实误差还不知道。

## 要排查的嫌疑点（逐条确认或排除，不要先入为主）

1. **诊断取错了格点**：`diagnostics()`（`d3q7.js:286` 起）用 `f[N+i] − f[2N+i]`，两项都取 x=1 的格点。穿过 x=1/x=2 截面的净通量应是 x=1 的 f₁（流向 +x）减去 x=2 的 f₂（流向 −x）。
2. **共轭界面方向不对称**：`d3q7.js:105` 只处理"孔隙 → 离聚物"，`d3q7.js:110` 却处理"离聚物 → 孔隙或缓冲层"。原代码 `streamoxy`（`mass_transfer.cu:417-458`）对"孔隙或缓冲层 → 离聚物"都做共轭处理。确认"缓冲层 → 离聚物"是否漏了。
3. **负值截断加质量**：`d3q7.js:210` 碰撞后把负分量截成 0（照原代码）。统计每步截断加进来的总量。
4. **反应计量**：`reaction()` 的 `src` 与 `collide()` 里 `m0 = rho − consumed` 是否一致，单位是否都是 mol/m³。
5. **还没到稳态**：默认 dt = 1e-11 下 3000 步远未收敛。用合理的 dt 跑到真正的稳态再比。

## 要做的

1. 新建 `lbm3d-cl/tools/mass-budget.mjs`：对默认结构逐步记录 Σc 的变化、入口净流入、反应消耗、截断增量、其余残差，输出到 `lbm3d-cl/out/mass-budget.csv`。质量收支正确时，残差应接近机器精度。用它定位误差来源。
2. 按排查结论修 `d3q7.js`。原则：
   - 与原代码不一致的地方（如嫌疑点 2）按原代码改。
   - 原代码本身导致的不守恒（如嫌疑点 3），**默认行为不改**，加参数开关（例如 `clampNegative`，默认 `true`），把影响量化写进汇报。
   - 不改公开接口（导出名、`Solver` 字段、各函数签名与语义）。
3. 补全 `lbm3d-cl/test/engine.test.mjs`，按任务 001 原要求：
   - 第 3 项：与 c_in·erfc(x / 2√(D t)) 比较，最大相对误差 ≤ 3%。
   - 第 5 项：默认结构跑到稳态（Σc 每 1000 步相对变化 < 1e-6），通量平衡误差 ≤ 1%。dt 选择要让孔隙、离聚物、缓冲层的 τ 都在 (0.5, 10] 内，测试里写明所用 dt 和各相 τ。若在合理 dt 下默认结构达不到 ≤1%，把误差和原因写进汇报，测试按实测值暂定阈值并注释原因，不要偷偷放宽。
   - 第 6 项：随机结构跑 50 步后逐个执行 6 个子步，每次执行后 `block` 的结果与按该子步定义直接计算的结果一致。
